# 号没了 · 运营计划

站长自己执行，不需要 Codex。

## 现状与目标

- 墙上的记录都是站长从公开帖子整理的，用户投稿是 0。
- **第一个月只有一个目标：拿到前 50 份真实的用户投稿。**

## 第 1–2 周：冷启动

- [ ] 先让 Codex 执行 `design/REVISION-2.md`，至少完成 R1（下线“使用小技巧”）和 R2（独立声明）再开始推广。
- [ ] 每周补 5–10 条有原帖、有日期的社区整理记录，保持墙上新鲜。
- [ ] 在关于页写明联系邮箱。原帖作者要求下架时，24 小时内处理。
- [ ] 自己做 10 张不同风格的墓志铭卡片，带 haomeile.rip 水印，作为传播素材。
- [ ] 在 Google Search Console 和 Bing 网站管理员工具提交 sitemap（见 `design/SEO.md` §9）。

**去哪里推广**（只去有人在讨论封号的地方）：

| 渠道 | 做法 |
|---|---|
| V2EX、Linux.do | 有人发帖说号没了的时候，回复里附一张卡片和链接 |
| 即刻、小红书 | 每周发“本周墓园”图文 |
| X 中文 AI 圈 | 跟进封号相关的讨论，附卡片 |
| Reddit 相关版块 | 英文版链接，同样只在相关讨论里出现 |

**不要做**：在 GitHub issue 里刷链接；群发广告帖；在别人的求助帖里只丢一个链接。

## 之后：固定节奏

| 频率 | 事项 |
|---|---|
| 每天 | 15 分钟审核投稿和举报 |
| 每周 | 一篇“本周墓园”：挑 3–5 块碑，配卡片图，发到上面的渠道 |
| 每月 | 一篇月报，只说“本站收到了什么”，严格按统计口径写 |
| 大事件当天 | 某家厂商出现大规模封号或政策变化时，当天整理一篇 |

**月报的写法**：可以写“本站这个月收到 23 份投稿，其中 14 份与账号停用有关”；不要写“某厂商封号率上升”“某厂商最爱封号”。

## 看哪些数字

不加第三方统计脚本，守住数据说明里的承诺。

- 每周投稿数、审核通过率（后台数据库）
- 墓志铭卡片下载次数（后端加一个只计数、不记录身份的接口）
- Google Search Console 的展示次数、点击次数、带来流量的搜索词
- 服务器日志或 Cloudflare 自带的访问统计（不需要在页面加脚本）

## 底线

- 不接买号、中转、代充、礼品卡、“防封”的广告或合作。
- 评论或投稿里出现防封技巧、绕过地区限制的方法，一律删除。
- 不用任何厂商的 logo 和吉祥物。
- 暂不变现。以后真要变现，最多开一个赞助入口。
- 这个站的价值在于“中立记录”。一旦沾上灰产，信誉和安全就都没了。
